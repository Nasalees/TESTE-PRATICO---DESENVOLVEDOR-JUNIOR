# Decisões Técnicas

## Principais decisões técnicas

- Utilização do Spring Boot para construção da API REST.
- Uso do Spring Data JPA para persistência de dados.
- Banco H2 em memória para simplificar execução e testes do projeto.
- Documentação da API utilizando Swagger/OpenAPI.
- Utilização de testes automatizados com JUnit e Mockito.
- Estruturação do projeto em camadas (Controller, Service e Repository).

---

# Prioridades e o que ficou de fora

## Prioridades

- Implementar o CRUD principal de agendamentos.
- Aplicar validações de negócio.
- Garantir organização básica da arquitetura.
- Criar documentação da API.
- Implementar testes automatizados básicos.

## O que ficou de fora

Os principais requisitos obrigatórios do desafio foram implementados.

Como melhorias futuras ou diferenciais adicionais, poderiam ser adicionados:

- Mais testes automatizados cobrindo outros cenários de negócio.
- Criação de uma interface frontend para consumo da API.
- Integração com Oracle para demonstrar compatibilidade com outro banco relacional além do H2.
- Documentação mais detalhada dos endpoints e respostas da API.
- Validações adicionais de dados, como validação completa de CPF.
- Melhor padronização das respostas de erro da aplicação.

# Uso de IA

Foi utilizada IA como apoio para:

- esclarecimento de dúvidas técnicas;
- apoio na configuração do Swagger;
- auxílio em testes automatizados;
- orientação sobre Git e GitHub;
- revisão de boas práticas no Spring Boot.

Todo o código gerado foi revisado, ajustado e validado manualmente durante o desenvolvimento do projeto.
